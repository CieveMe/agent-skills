# AI 辅助软件开发最佳实践

## 适用场景
- 使用 AI 编程助手（Gemini/Claude/Cursor 等）进行项目开发
- 多 Conversation 长期开发场景

## 1. Token 节省技巧

| 技巧 | 原因 | 节省比 |
|------|------|:------:|
| **900 Step 前主动重开会话** | 上下文堆积导致 ~70% token 浪费在读旧内容 | 70% |
| **`view_file(startLine, endLine)` 指定行范围** | 全文读取浪费大量 token | 50-80% |
| **环境变量/配置锁定到 task.md** | 避免 AI 每次都搜索配置文件 | 30% |
| **一次确认多个方案** | 减少来回迭代轮次 | 40% |
| **Skill 文件沉淀知识** | 新会话直播读取，免重复解释上下文 | 60% |

## 2. 防重复劳动

### 2.1 创建 Skill/Knowledge 文件
```markdown
# 在项目根目录创建 .agents/skills/xxx/SKILL.md
# AI 新会话时自动读取，不需要重新解释业务上下文
```

### 2.2 task.md 记录进度
```markdown
- [x] 已完成：数据库表设计
- [x] 已完成：后端 CRUD
- [/] 进行中：微信支付集成
- [ ] 待做：前端联调
```
**效果**：AI 不会重做已完成的工作

### 2.3 交接提示词
```markdown
# 会话结束时写好：
"下一个会话需要继续的工作：
1. xxx 的 bug 已定位在 YYY.java:123 行
2. 当前环境配置在 task.md 中
3. 禁止恢复 Mock 支付代码（见 skill_he.md 第 5 节）"
```

## 3. 相同错误反复修改不解决的 5 大根因

### 3.1 模型切换导致上下文丢失
- **现象**：切换 AI 模型后，新模型不知道之前的决策
- **对策**：切换后先让 AI 读取 skill/task 文件

### 3.2 AI "好心" 恢复被删代码 ⭐ 最危险
- **现象**：明明删了 Mock 代码，AI 又加回来
- **对策**：**物理删除**而非注释；在 skill 文件中写"禁止恢复 XXX"
- **案例**：支付 Mock 代码被恢复 3 次

### 3.3 替换操作破坏 import/方法体
- **现象**：`multi_replace_file_content` 替换区域包含 import → import 丢失/重复
- **对策**：import 修改与业务代码修改**分两次独立操作**

### 3.4 YAML 缩进错误反复出现
- **现象**：`@ConfigurationProperties` 绑定值全为 null，无报错
- **对策**：改用 `@Value` 显式注入，缺失即启动失败

### 3.5 配置两处不一致
- **现象**：YAML 配好了但 DB 配置表没同步（如微信 AppSecret）
- **对策**：在 task.md 中用表格列出所有需同步的配置点

## 4. AI 辅助开发的适用边界

| 场景 | AI 表现 | 建议 |
|------|---------|------|
| CRUD 脚手架 | ⭐⭐⭐⭐⭐ 极佳 | 放心用 |
| 配置文件 | ⭐⭐⭐⭐ 好 | 需人工审 YAML 缩进 |
| 算法逻辑 | ⭐⭐⭐⭐ 好 | 边界条件需特别注意 |
| 支付/安全 | ⭐⭐ 危险 | **必须人工逐行审查** |
| UI/Logo 设计 | ⭐⭐ 一般 | 品牌素材直接用原始文件 |
| 部署运维 | ⭐⭐⭐ 可用 | Windows→Linux 跨平台坑多 |
