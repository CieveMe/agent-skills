# 数据库变更操作安全规则

## 强制动作：写 SQL 前，先拆解用户指令为条件清单

在生成任何 UPDATE / DELETE / INSERT 语句之前，必须先执行以下步骤：

1. **逐词拆解用户指令**，将每一个修饰词、定语、状语提取出来
2. **列成条件清单**，每个词对应一个 SQL 条件（或标注"无需映射"并说明理由）
3. **将清单展示给用户确认**，确认后再写 SQL

### 示例

用户指令：`正在进行中的活动1的奖品名称中"100元、200元、500元"的分别改成不加"元"的`

拆解清单：

| 限定词 | SQL 条件 |
|--------|----------|
| 正在进行中的 | `a.status = 0` |
| 活动1 | `a.name = '活动1'` |
| 奖品名称中 | 操作字段：`lottery_prize.name` |
| 100元、200元、500元 | `p.name IN ('100元','200元','500元')` |
| 改成不加"元"的 | `SET name = REPLACE(name, '元', '')` |

## 为什么需要这个规则

自然语言中的限定词容易被错误归类为"描述性背景"而非"过滤条件"，尤其是当操作指令本身看起来已经"足够明确"的时候。强制拆解动作能打断这种跳跃式思维，确保每个词都被显式处理。
